# OWASP Top 10:2025 — review checklist

Source: https://owasp.org/Top10/2025/ (final 2025 edition; verified 2026-10).
Changes vs 2021: SSRF folded into A01; **A03 Software Supply Chain Failures**
(replaces "Vulnerable and Outdated Components", broader); **A10 Mishandling of
Exceptional Conditions** is new; Security Misconfiguration rose to #2.

For each item, mark **Pass / N/A (reason) / Finding** against the final diff.

## A01 Broken Access Control (includes SSRF)
- Every route has an authentication dependency; no "temporarily public" routes.
- Function-level: role/permission checked server-side for every action (not just hidden in the UI).
- Object-level (IDOR/BOLA): every lookup by ID also filters by the caller's `tenant_id`; cross-tenant → 404.
- Tenant/owner/role taken from the verified token, never from body/query/headers the client controls.
- Mass assignment: write schemas don't expose `tenant_id`, `role`, `is_admin`, `owner_id`, status fields.
- CORS: explicit origin allow-list; no `*` with credentials.
- Path/file access constrained to a base dir (resolve + `is_relative_to`).
- SSRF: user-influenced URLs pass scheme allow-list + resolved-IP block (127/8, 10/8, 172.16/12, 192.168/16, 169.254/16, ::1, fc00::/7, metadata hosts); no redirects to blocked targets.

## A02 Security Misconfiguration
- No debug mode, default creds, sample endpoints, or stack traces in prod.
- Security headers present (CSP, HSTS, X-Content-Type-Options, frame-ancestors/X-Frame-Options, Referrer-Policy).
- Cookies: `HttpOnly`, `Secure`, `SameSite` set appropriately.
- Containers: non-root user, minimal base, no secrets baked into images, read-only FS where possible.
- OpenAPI/docs endpoints restricted in prod; directory listing off.
- New config has a secure default; insecure options require explicit opt-in.

## A03 Software Supply Chain Failures
- New deps justified, pinned (exact or hash), maintained, licence-compatible.
- `pip-audit` / `npm audit` clean for added deps (or exceptions documented).
- Lockfiles regenerated by tooling, committed.
- CI actions pinned (prefer SHA); workflow `permissions:` minimal.
- No `curl | sh` installs; downloaded artifacts verified (checksum/signature).
- Build provenance: probe/agent release artifacts signed/sealed per `probe/SEALING.md`.

## A04 Cryptographic Failures
- Data classified; secrets/credentials encrypted at rest; TLS for all transport (probe↔manager included).
- Passwords: bcrypt/argon2 via vetted lib; never reversible.
- Tokens from `secrets`, ≥128 bits; constant-time comparison (`hmac.compare_digest`).
- JWT: algorithm pinned, `aud`/`exp` validated, no `none`, secret from settings.
- No MD5/SHA1/ECB/static IVs for security; no home-made crypto.
- Sensitive data not cached, not in URLs, not in logs.

## A05 Injection
- SQL: ORM expressions or bound params; no f-string/`.format` into `text()`.
- OS command: `subprocess.run([...], shell=False)`; scan targets/args validated (IP/CIDR/hostname/port regex or `ipaddress`).
- XSS: React escapes by default — any `dangerouslySetInnerHTML` is sanitised (DOMPurify) and justified; no user data in `href="javascript:"`.
- Template / LDAP / NoSQL / header / log injection (strip CR/LF) considered.
- Code injection: no `eval`/`exec`/`pickle.loads`/`yaml.load` (use `safe_load`) on untrusted data.
- LLM prompt injection: see `owasp-api-llm.md`.

## A06 Insecure Design
- Threat model done (Phase 0); abuse cases have tests.
- Business-flow limits (e.g. scan launches, report exports, invites) rate-limited/quota'd.
- Tenancy isolation designed in, not bolted on.
- Security-relevant decisions recorded (ADR when architectural).

## A07 Authentication Failures
- Login/MFA/reset rate-limited and lockout/backoff applied; generic error messages (no user enumeration).
- Session/refresh tokens rotated, revocable, bounded lifetime; logout invalidates server-side.
- MFA cannot be bypassed via alternative flows (API tokens, password reset).
- PATs/API keys hashed at rest, scoped, expirable.
- Probe enrolment: one-time, short-lived, bound to device identity.

## A08 Software or Data Integrity Failures
- No unsafe deserialization of untrusted data (pickle, unsafe YAML, msgpack ext types).
- Agent updates / commands from manager verified (signature/version gate) before execution.
- Webhooks/callbacks authenticated (HMAC + timestamp, replay window).
- CI/CD can't be modified by untrusted PRs to exfiltrate secrets (`pull_request_target` caution).

## A09 Security Logging & Alerting Failures
- Auth events, authz denials, privilege changes, config changes, scan launches, exports are audit-logged with actor, tenant, target, result.
- Logs exclude secrets/tokens/passwords/PII beyond need; structured (structlog).
- Log injection prevented (structured fields, not concatenated strings).
- Alertable events emit metrics/logs that can be alerted on.

## A10 Mishandling of Exceptional Conditions (new)
- Fail closed: exceptions in auth/authz/validation deny access.
- No bare `except:` / `except Exception: pass` that swallows security-relevant errors.
- Errors returned to clients are generic; details logged with correlation ID.
- Partial failures leave consistent state (transactions, idempotency keys, cleanup in `finally`).
- Timeouts, retries with backoff and caps; resource exhaustion handled (no unbounded retry/queue).
- Null/missing values and unexpected types handled explicitly.
